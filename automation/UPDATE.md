# 수집기 v2 업데이트 — 기존 저장소를 유지하세요

## 이번 변경

### 웹페이지: 자동 발견을 행사 화면과 연결

기존에는 개인 등록 행사(localStorage)와 공개 자동 피드가 분리되어 자동 조사 센터의 발견이 대시보드·행사 모니터링에 보이지 않았습니다. 이제 **저장소를 옮기지 않고 읽기 전용으로 함께 표시**합니다.

- 내 등록 행사와 자동 후보를 별도 상태·출처 필터로 구분합니다.
- 원본 20건은 독립 행사 20개가 아닙니다. 첫 피드에는 TEAMZ의 전시·스테이지·기모노 대여·VIP 행사·같은 페이지·2026년 정보가 섞여 있었습니다.
- 감시 브랜드와 명시된/언급된 연도에 따른 보기용 묶음으로 집계합니다. 현재 첫 피드는 전체 4묶음, 대상 기간·미확정 필터에서 3묶음입니다. 이를 실제 개최 확정 수나 정밀한 동일행사 판정이라고 표시하지 않습니다.
- 모든 원본 ID·URL은 자동 조사 센터와 후보 상세에 유지합니다. 2026년 근거는 기간 필터를 해제해 볼 수 있습니다.
- 개인 행사로 저장하려면 ‘내 행사로 등록’에서 공식명·일정·지역·근거를 확인하고 저장해야 합니다. 자동으로 개인 기록을 생성하거나 기존 메모를 덮어쓰지 않습니다.
- 명시적으로 연결된 원본 ID가 있는 개인 기록은 자동 후보 행과 이중 표시하지 않습니다. 이름이 비슷하다는 이유만으로 기존 기록을 자동 병합하지 않습니다.

### 외부 수집기: RSS 실패 보완

RSS가 실패하면 기사 제목이 확보되는 것은 아닙니다. 기존 조사자료의 행사명과 실제 읽은 페이지 제목을 단서로 사용합니다.

1. 이미 알고 있는 출처 URL, 해당 출처의 이전 발견 URL, 홈페이지를 확인합니다.
2. 페이지의 행사·프로그램·스피커 관련 링크를 제목·키워드로 점수화합니다.
3. 사이트가 직접 광고하는 공개 RSS/Atom이 있으면 읽어 관련 링크를 찾습니다.
4. robots.txt가 광고하는 사이트맵 또는 `/sitemap.xml`을 실제 요청하여 확인합니다. 파일 경로를 만들었다고 접근 성공으로 간주하지 않습니다.
5. 같은 출처 호스트의 후보 링크에 실제로 접속합니다. 본문에 2027년 언급이 있는 경우에만 ‘대체 링크 발견’으로 기록하고, 여전히 사실 검수가 필요한 상태로 둡니다.
6. 접근 성공 URL·제목·확인 시각·탐색 방법·실패·미시도를 공개 피드에 기록합니다.

추가로 **GDELT 공개 Doc API**를 별도 뉴스 색인으로 조회합니다. API 키는 필요하지 않습니다. 질의 2개·질의당 최대 10개 후보, 원문 접근 확인 3개로 제한하고 API 호출 간 최소 5초를 둡니다. 원문이 막힌 경우 질의당 제목 1개를 한도로 API에 정확한 제목을 다시 질의하고, 다른 URL 최대 2개에 실제 접속하여 제목 유사도를 확인합니다. 실패 원문은 여전히 실패로 남기고, 성공한 대체 URL·확인 시각·제목 일치 여부를 따로 기록합니다.

이 환경의 공개 API 시험 요청은 JSON `{}`(결과 없음)를 반환했습니다. API 응답을 받았다는 것과 실제 대체 기사를 확보했다는 것은 다르며, 운영 GitHub에서의 성공률은 업데이트 후 확인해야 합니다. API 장애·색인 누락·속도 제한은 실패 또는 0건으로 명시합니다.

**접근 제한·로그인·robots를 우회하지 않습니다. Google/Bing 검색 링크는 기자가 누르는 수동 검색 버튼이며, 검색엔진 결과를 몰래 자동 수집하는 기능이 아닙니다.** Google 뉴스 RSS 자체가 복구된 것은 아닙니다. 별도 공개 뉴스 색인 탐색과 알려진 출처 내부 탐색의 범위·결과를 나누어 표시합니다.

시간·요청량을 제한하기 위해 기본은 **회당 8개 행사군, 행사군당 최대 7회 확인**입니다. 실패한 31개 감시 행사군을 순환하고, 미시도는 성공으로 세지 않습니다. 7개 일반 키워드 검색의 대체 전수 탐색은 제공하지 않습니다. robots 실패는 해당 실행 안에서 캐시해 같은 서버에 반복 요청하지 않습니다.

## GitHub에 적용하는 순서

이 웹사이트를 수정했다고 이미 설치한 GitHub 저장소의 코드가 자동으로 바뀌지는 않습니다. 다음 3개 파일만 교체합니다. **워크플로·예약 변수·관측 이력·개인 기록은 삭제하거나 재설정하지 마세요.**

1. 웹사이트 **자동 조사 센터 → 연결·시작 안내 → 수집기 v2 업데이트 받기**를 눌러 ZIP을 받고 압축을 풉니다.
2. GitHub의 기존 **automation 폴더**를 엽니다.
   https://github.com/dooney37/tokenomy-korea-monitor/tree/main/automation
   - 이 폴더에서 `Add file → Upload files`를 선택합니다.
   - ZIP에서 푼 `automation` 폴더 안의 **collector.py, test_collector.py 두 파일만** 올립니다.
   - 업로드 경로가 `automation/collector.py`, `automation/test_collector.py`인지 확인하고 Commit changes 합니다.
   - 상위 첫 화면에 올리거나 automation 폴더를 다시 감싸 `automation/automation/`으로 만들지 마세요.
3. GitHub의 기존 **data 폴더**를 엽니다.
   https://github.com/dooney37/tokenomy-korea-monitor/tree/main/data
   - `Add file → Upload files`에서 ZIP의 `data/monitor-plan.json` 파일 하나를 올립니다.
   - 저장 위치가 `data/monitor-plan.json`인지 확인하고 Commit changes 합니다.
4. Actions → **RWA Radar — twice-daily research → Run workflow**로 1회 실행합니다. 기존 관측 상태는 읽어서 유지하고 새 결과만 반영합니다.
5. 웹사이트 **자동 조사 센터 → 결과 새로고침**을 누릅니다. ‘연결·시작 안내’에 **현재 피드 수집기: v2.0**이 표시되고, ‘실행 기록’에 대체 탐색 내역이 생겨야 적용이 확인됩니다.

순환 대기인 행사군은 다음 회차에 조사하므로 한 번의 실행으로 모든 행사군이 복구되는 것은 아닙니다. RSS 실패는 계속 실패로 남길 수 있습니다. 대체 탐색으로 복구한 범위와 광범위한 뉴스 탐색 실패를 함께 보아야 합니다.

## 검증 및 남은 한계

- 기존 14개 + 대체 탐색·보존·순환 등을 추가한 **30개 Python 단위 테스트**를 브라우저 Python 환경에서 통과했습니다. 네트워크는 테스트용 응답으로 검증했습니다.
- 실제 첫 피드의 원본 보존·4묶음/기본 3묶음·기존 개인 기록 무변경·출처/기간 필터를 브라우저에서 확인했습니다.
- 실제 GitHub 실행 환경의 대체 사이트 접근 성공률·신규 결과·v2 배포는 **업데이트 후 확인해야 합니다**. 현재 v1 피드에 아직 없는 대체 링크를 확보했다고 주장하지 않습니다.
- 구조화되지 않은 연사표, JS 렌더링, 이미지·PDF·비공개 행사는 추가 대응이 필요합니다. 접근 가능 페이지나 2027년 언급만으로 개최일·금융 연관성·인물 소속을 확정하지 않습니다.
