# 수동 모니터링·지정 URL 조사 v3

## 무료 구성의 실행 방식

GitHub Pages는 정적 웹페이지입니다. 웹페이지 버튼만으로 로그인된 GitHub의 workflow_dispatch를 호출할 수 없고, 브라우저에 비밀번호/토큰을 보관하지 않습니다. 버튼 → GitHub 실행 화면 → 소유자가 Run workflow 승인 → Python 수집 → 관측 이력 보존 → Pages 피드 발행 → 웹페이지가 피드 조회 순서입니다. 실행 버튼을 눌렀다는 사실만으로 접수/성공으로 표시하지 않습니다.

전체 모니터링은 자동 조사 센터의 ‘수동 모니터링 실행’ → GitHub에서 실행 승인 → Run workflow → target_url 비움 → Run workflow. 예약 활성 변수와 관계없이 소유자가 직접 실행할 수 있습니다. 예약 자체를 고치는 버튼은 아니며 실행 한도/권한/장애/robots 제한은 우회하지 않습니다.

지정 URL은 공개 페이지 주소 입력 → 공개 동의 → ‘이 링크 조사 요청 준비’ → 주소 복사 → GitHub 실행 화면의 Run workflow → target_url 칸에 붙여넣기 → Run workflow. target_url 입력란이 없다면 아래 워크플로 교체가 필요합니다. URL을 GitHub 화면에 자동 입력하거나 입력만으로 수집을 시작하는 기능은 아닙니다.

수집 후 ‘조사결과 다시 읽기’ → ‘지정 URL 조사 결과만 보기’ → 근거·상세 보기 → 추출 연사 검토·선택 등록. 기록은 이 브라우저에만 저장됩니다. 새 행사 정보를 검수하거나 기존 행사를 선택합니다. 선택한 인물의 이름·소속·근거 URL과 공식 확인 동의가 있어야 저장됩니다. 같은 행사/정규화된 이름/소속이 같은 인물은 제외하며 기존 행사·연사·섭외 상태·메모를 덮어쓰지 않습니다. 이름·소속이 바뀌면 다른 후보로 보일 수 있어 직접 확인해야 합니다.

## 수집기 저장소 업데이트 (기존 상태 유지)

자동 조사 센터의 ‘수동 조사 기능 업데이트 파일’ ZIP을 받고 압축을 풉니다. 웹페이지용 저장소가 아닌 기존 수집기 저장소 https://github.com/dooney37/tokenomy-korea-monitor 에 적용합니다.

1. 기존 automation 폴더를 열고 Add file → Upload files에서 collector.py, test_collector.py 두 파일만 교체·Commit changes.
2. 기존 .github/workflows 폴더를 열고 rwa-monitor.yml 하나만 교체·Commit changes. ZIP의 .github는 숨김 폴더일 수 있습니다. 파일을 찾기 어려우면 기존 워크플로를 Edit하고 ZIP 안 파일의 전체 텍스트로 교체합니다. 상위 첫 화면이나 .github/workflows/workflows처럼 잘못 중첩하지 않습니다.
3. .monitor-state, data/monitor-plan.json, 예약 변수 RADAR_ENABLE_SCHEDULE는 지우거나 초기화하지 않습니다. v2 설정이 있는 기존 사용자를 위한 증분 업데이트입니다. 처음 설치하는 경우 자동화 설치 파일을 사용합니다.
4. 기본 브랜치 main에서 워크플로의 Run workflow를 열었을 때 target_url 칸이 보이는지 확인합니다. 우선 공개 페이지 1개로 실행하고 실제 Pages 배포가 끝나는지 확인합니다.
5. 웹페이지에서 결과 새로고침 후 collector_version 3.0과 지정 URL 실행 기록(mode=target_url), 대상 URL·실행 시각을 확인합니다.

이 프로젝트의 코드 변경으로 이미 운영 중인 외부 GitHub 코드가 자동 갱신되지는 않습니다. 공개 웹페이지용 저장소도 편집기 미리보기의 ‘무료 웹페이지 공개’에서 받은 최신 ZIP으로 갱신해야 새 버튼이 나타납니다. 두 저장소를 섞지 마세요.

## 수집 범위·개인정보

- 지정 URL의 HTML 1페이지만 읽습니다. Event JSON-LD와 해당 Event의 performer(Person)만 연사 후보로 추출합니다. 페이지 내 임의의 Person을 행사 발표자로 추정하지 않습니다.
- 구조화 Event가 없으면 HTML 본문 발췌와 ‘연사 자동 추출 없음’을 기록합니다. PDF·이미지·JavaScript 전용 명단·로그인·차단 페이지는 자동 분석하지 않습니다. 본문을 직접 읽어 기존 행사·스피커 입력 양식을 사용할 수 있습니다.
- 직접 접속 제한·robots 규칙은 지킵니다. 지정 URL 모드는 리디렉션을 자동 추적하지 않으므로 리디렉션 오류 시 브라우저의 최종 공개 URL을 넣습니다. 내부망·인증정보·쿼리/해시·비표준 포트는 지원하지 않습니다. 쿼리가 필수인 사이트는 수동 조사합니다.
- URL과 조사 결과는 GitHub 이력·공개 피드에 공개됩니다. 비공개 링크·서명 URL·연락처·토큰을 넣지 않습니다. 공개 동의는 사이트 접근권한을 우회하는 허가가 아닙니다.
- 지정 URL 조사 결과의 페이지 접근 성공은 전체 모니터링·예약 복구·공식성·참석 확정을 뜻하지 않습니다. 마지막 전체 성공 시각과 기존 누적 관측·페이지 해시·순환 위치는 보존합니다. 지정 URL은 다음 예약의 영구 감시목록에 자동 등록되지 않습니다.
- 같은 이름·소속이라도 동명이인일 수 있습니다. 자동 후보를 곧바로 확정 섭외자나 참석자로 저장하지 않습니다. 개인 등록 시 기본 상태는 ‘관심 후보’입니다.

## 운영 확인은 별도

개발 테스트는 테스트용 응답으로 수행합니다. 외부 GitHub의 실제 실행·발행 성공 및 특정 행사 페이지의 추출 가능 여부는 소유자가 업데이트 후 확인해야 합니다.
