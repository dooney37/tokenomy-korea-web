이 브라우저의 개인 메모·백업·관측 이력은 포함하지 않습니다.

ZIP을 받은 뒤 아래 4단계를 따라 주세요.

기존 리서치 저장소는 그대로 두세요.

tokenomy-korea-monitor는 자동 조사 피드를 발행 중입니다. 이번 웹페이지는 새 공개 저장소에 올립니다. 기존 피드·예약 설정을 바꾸거나 지우지 않습니다.

01

새 공개 저장소 만들기

GitHub에 로그인한 뒤 새 저장소를 만듭니다. 이름은 예를 들어 tokenomy-korea-web, 공개 범위는 Public으로 선택하고 Create repository를 누릅니다.

GitHub 새 저장소 만들기 ↗

이름은 예시입니다. 기존 저장소와 다른 이름을 사용하세요. 공개 저장소의 소스 코드·조사 계획은 누구나 볼 수 있습니다.

02

압축을 풀고 파일·폴더 업로드

받은 ZIP을 먼저 풉니다. 새 저장소의 uploading an existing file 또는 Add file → Upload files에서 압축 안의 파일·폴더를 올리고 Commit changes로 저장합니다.

index.html　← 첫 화면에 있어야 합니다
publish.html
css/　js/　data/　automation/
PUBLIC-WEBSITE.md　README.md　.nojekyll

ZIP 자체나 ZIP을 감싼 상위 폴더를 올리지 마세요. 업로드 후 첫 화면에 index.html과 위 폴더들이 보이는지 확인하세요. .nojekyll은 숨김 파일이며 누락돼도 이 사이트의 기본 파일은 동작합니다.

파일들이 폴더 없이 한곳에 올라갔나요?

폴더 경로가 사라지면 화면이 깨집니다. 새 저장소에서 각 폴더를 먼저 만들고, 해당 폴더 안에서 파일만 업로드하세요. 예: Add file → Create new file에서 css/README.md를 만들고 저장 → css 폴더 열기 → Upload files로 style.css, monitor.css, publish.css를 올립니다. js, js/vendor, data, automation도 같은 방식으로 원래 경로를 유지합니다. 기존 리서치 저장소의 파일은 수정하지 마세요.

개인 데이터 백업 JSON, 연락처, 비공개 메모, 비밀번호·토큰은 절대 업로드하지 마세요.

03

Pages에서 무료 공개 켜기

새 저장소의 Settings → Pages를 엽니다. Build and deployment의 Source는 Deploy from a branch, Branch는 main, 폴더는 /(root)를 선택한 뒤 Save를 누릅니다.

이번에는 GitHub Actions가 아니라 ‘Deploy from a branch’입니다. 수집기용 예약 변수나 별도의 워크플로를 설정할 필요가 없습니다. GitHub Free의 공개 저장소 Pages를 이용하며 서비스의 용량·트래픽·이용약관 제한은 적용됩니다. 유료 도메인은 필요 없습니다.

04

실제로 발급된 주소 확인하고 공유

배포가 끝나면 Settings → Pages에 표시되는 Visit site 또는 Your site is live at…의 주소를 엽니다. 첫 배포는 몇 분 걸릴 수 있습니다. 주소를 직접 추측하지 말고 실제 표시된 링크를 복사해 공유하세요.

  • 대시보드와 자동 후보가 보이는지 확인합니다.
  • 자동 조사 센터에서 공개 피드 수신 시각을 확인합니다.
  • 휴대전화에서도 같은 링크가 열리는지 확인합니다.

아직 이 안내만으로 사이트가 배포되거나 공유 주소가 생성되는 것은 아닙니다. 404라면 배포 완료·main/root 설정·첫 화면의 index.html 위치를 먼저 확인하세요.
